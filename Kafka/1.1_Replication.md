### Replication

```text
• Replication means keeping copies of the same partition on multiple brokers.
• Kafka replicates Partitions, not Topics.
• Each copy of a partition is called a Replica.
• Replication provides fault tolerance and high availability.
• If one broker fails, another broker with a replica can continue serving data.
```


# Why Replication?

Suppose your Kafka Cluster has only **one Broker**.

```text
Kafka Cluster

┌──────────────┐
│   Broker 1   │
│              │
│ orders-P0    │
└──────────────┘
```

Now imagine:

* Hard disk fails.
* Server crashes.
* Power failure.

What happens?

```text
Broker 1

❌ Down
```

Question:

Where are the events?

They are gone.

That means:

* Orders are lost.
* Payments are lost.
* Notifications are lost.

This is unacceptable in production.

So Kafka introduces **Replication**.

---

# Definition

> **Replication means keeping copies of the same partition on multiple brokers.**

Notice the wording.

Kafka replicates **Partitions**, **not Topics**.

---

# Example

Suppose Topic:

```text
orders

↓

Partition 0
```

Instead of storing it only on Broker 1,

Kafka stores copies.

```text
Broker 1

orders-P0
```

```text
Broker 2

orders-P0 (Copy)
```

```text
Broker 3

orders-P0 (Copy)
```

Now there are three copies of the same partition.

---

# Why only Partitions?

Remember:

A Topic is just a logical name.

Actual data lives inside partitions.

Therefore Kafka replicates **Partitions**.

Never Topics.

---

# What is a Replica?

Every copy is called a **Replica**.

Example:

```text
Broker 1

orders-P0
```

↓

Replica

```text
Broker 2

orders-P0
```

↓

Replica

```text
Broker 3

orders-P0
```

↓

Replica

All three are replicas of the same partition.

---

# Visual

```text
               orders Topic

                    │

             Partition 0

        ┌──────┴──────┐

        ▼             ▼

Broker 1         Broker 2

Replica          Replica

        ▼

Broker 3

Replica
```

Notice:

The **partition is the same**.

Only its copies are on different brokers.

---

# Why is Replication Useful?

Suppose Broker 1 crashes.

```text
Broker 1 ❌
```

Copies still exist.

```text
Broker 2 ✅

Broker 3 ✅
```

Kafka continues serving data.

No data loss.

No application failure.

### Doubt Note

* A broker can store **multiple partitions of the same topic**, including its own partition and replica partitions of other brokers.
* If a broker fails, Kafka promotes a replica on another broker to become the **Leader**.
* The new leader broker **serves** that partition to consumers.
* **Brokers do not process events**; they only **store and serve** partitions. **Consumers** read the events and execute the business logic.
