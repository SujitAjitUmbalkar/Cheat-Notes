# 6. One-Time Kafka Setup

These commands are executed **only once** after installing Kafka.

---

## Step 1 Generate Cluster ID

```powershell
.\bin\windows\kafka-storage.bat random-uuid
```

Example

```
FGPPjsgNSoCeRwPPGnknag
```

Save this ID.

---

## Step 2 Format Storage

Kafka 4.x uses **KRaft Mode**.

Format storage

```powershell
.\bin\windows\kafka-storage.bat format ^
--standalone ^
-t <ClusterID> ^
-c config\server.properties
```

Example

```powershell
.\bin\windows\kafka-storage.bat format ^
--standalone ^
-t FGPPjsgNSoCeRwPPGnknag ^
-c config\server.properties
```

Expected

```
Formatting dynamic metadata voter directory...
```

> **Important**
>
> Formatting is required only once.
>
> Do **NOT** run this command every time you start Kafka.

---

# 7. Start Kafka Broker

Every day whenever you want to use Kafka

```powershell
.\bin\windows\kafka-server-start.bat config\server.properties
```

Expected

```
Kafka Server started
```

Keep this terminal running.

# 8. Create Topic

Open another **PowerShell** window.

Go to Kafka directory

```powershell
cd C:\Users\jeetu\Downloads\kafka_2.13-4.3.1
```

Create topic

```powershell
.\bin\windows\kafka-topics.bat ^
--create ^
--topic first-topic ^
--bootstrap-server localhost:9092
```

Output

```
Created topic first-topic.
```

# 19. Key Takeaways

* Kafka 4.3.1 uses **KRaft mode** by default (no ZooKeeper).
* Storage formatting is a **one-time initialization** step.
* After the initial setup, you only need to **start the broker** for daily work.
* The console producer and consumer are primarily **learning and testing tools**. In Spring Boot applications, your Java code (`KafkaTemplate` and `@KafkaListener`) will produce and consume messages instead.
* On Windows, use the **`.bat` scripts** inside the `bin\windows` directory instead of the Linux `.sh` scripts.
* The installation and startup flow above aligns with the official Kafka 4.3.1 quickstart, with the addition of the `--standalone` formatting option required for Kafka 4.x in KRaft mode.
