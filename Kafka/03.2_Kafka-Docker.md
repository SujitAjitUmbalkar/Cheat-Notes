# Kafka in Docker (KRaft Mode) – Notes

# Purpose

Running Kafka in Docker provides:

* No need to install Kafka manually.
* Same environment on every machine.
* Easy start/stop using Docker Compose.
* Isolated environment (doesn't affect your OS).
* Easy to delete and recreate Kafka whenever needed.
* Best approach for Spring Boot local development.

---

# Architecture

```text
Spring Boot Application
        │
        │ localhost:9092
        ▼
+---------------------------+
| Docker Container          |
|                           |
|   Apache Kafka (KRaft)    |
|                           |
+---------------------------+
```

# Step 3 — Write `docker-compose.yml`

This file tells Docker:

* Which containers to create.
* Which image to download.
* Port mappings.
* Kafka configuration.
* UI configuration (Kafbat).

```yaml
version: '3.8' # Docker Compose file format version.

services: # Defines all containers to be created.

  kafka: # Kafka broker service.
    image: confluentinc/cp-kafka:7.6.0 # Kafka Docker image.
    container_name: kafka-kraft # Custom name for the Kafka container.

    ports:
      - "9092:9092" # Exposes Kafka on localhost:9092.

    environment: # Kafka configuration.

      KAFKA_NODE_ID: 1 # Unique ID of this Kafka broker.

      KAFKA_PROCESS_ROLES: 'broker,controller' # Runs as Broker and Controller.

      KAFKA_LISTENERS: 'PLAINTEXT://0.0.0.0:29092,CONTROLLER://0.0.0.0:29093,PLAINTEXT_HOST://0.0.0.0:9092' # Ports on which Kafka listens.

      KAFKA_ADVERTISED_LISTENERS: 'PLAINTEXT://kafka:29092,PLAINTEXT_HOST://localhost:9092' # Addresses advertised to clients.

      KAFKA_LISTENER_SECURITY_PROTOCOL_MAP: 'CONTROLLER:PLAINTEXT,PLAINTEXT:PLAINTEXT,PLAINTEXT_HOST:PLAINTEXT' # Security protocol for each listener.

      KAFKA_INTER_BROKER_LISTENER_NAME: 'PLAINTEXT' # Listener for broker communication.

      KAFKA_CONTROLLER_LISTENER_NAMES: 'CONTROLLER' # Listener for the KRaft controller.

      KAFKA_CONTROLLER_QUORUM_VOTERS: '1@kafka:29093' # Controller quorum configuration.

      KAFKA_OFFSETS_TOPIC_REPLICATION_FACTOR: 1 # Replication factor for offset topic.

      KAFKA_GROUP_INITIAL_REBALANCE_DELAY_MS: 0 # No delay before consumer rebalance.

      KAFKA_TRANSACTION_STATE_LOG_MIN_ISR: 1 # Minimum replicas required for transactions.

      KAFKA_TRANSACTION_STATE_LOG_REPLICATION_FACTOR: 1 # Replication factor for transaction logs.

      KAFKA_LOG_DIRS: '/tmp/kraft-combined-logs' # Location where Kafka stores its data.

      CLUSTER_ID: 'MkU3OEVBNTcwNTJENDM2Qk' # Unique identifier for the Kafka cluster.

  kafbat: # Kafka Web UI.
    image: ghcr.io/kafbat/kafka-ui:latest # Latest Kafbat image.
    container_name: kafbat # Custom name for the Kafbat container.

    ports:
      - "8080:8080" # Opens Kafbat at http://localhost:8080.

    environment: # Kafbat configuration.

      DYNAMIC_CONFIG_ENABLED: "true" # Enables dynamic cluster configuration.

      KAFKA_CLUSTERS_0_NAME: "Local Kafka" # Cluster name shown in the UI.

      KAFKA_CLUSTERS_0_BOOTSTRAPSERVERS: "kafka:29092" # Kafka broker address inside Docker.

    depends_on:
      - kafka # Starts Kafka before Kafbat.
```

# Step 4 — Start Containers

### Command

```bash
docker compose up -d
```

### Description

Reads `docker-compose.yml`.

If images are not present:

* Downloads them.

Then:

* Creates containers.
* Creates network.
* Starts containers.

### `-d`

Detached mode.

Runs containers in the background.

# Common Docker Commands Summary

| Command                            | Purpose                            |
| ---------------------------------- | ---------------------------------- |
| `docker compose up -d`             | Start containers in the background |
| `docker compose down`              | Stop and remove containers         |
| `docker compose stop`              | Stop containers                    |
| `docker compose start`             | Start existing containers          |
| `docker compose restart`           | Restart containers                 |
| `docker ps`                        | Show running containers            |
| `docker ps -a`                     | Show all containers                |
| `docker logs <container>`          | View container logs                |
| `docker exec -it <container> bash` | Open shell inside a container      |
| `docker images`                    | List downloaded images             |
| `docker volume ls`                 | List Docker volumes                |
| `docker network ls`                | List Docker networks               |
| `docker system prune`              | Remove unused Docker resources     |

These notes cover the complete lifecycle of running Kafka in Docker—from verifying Docker, starting Kafka, interacting with topics and messages, to stopping and cleaning up the environment.
