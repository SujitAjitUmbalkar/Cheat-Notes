# Kafka Notes – Part 6 : Offsets

---

# 1. What is an Offset?

**Definition**

> An **Offset** is the unique sequential number assigned by Kafka to every event within a **Partition**.

Example:

```text
Partition 0

Offset 0 → OrderPlaced

Offset 1 → PaymentCompleted

Offset 2 → OrderShipped

Offset 3 → OrderDelivered
```

Kafka assigns offsets automatically.

---

# 2. Why do we need Offsets?

Offsets help Kafka identify each event inside a Partition.

Instead of saying:

> "Give me the third event."

Kafka uses:

```text
Offset 2
```

Every event has its own unique Offset within its Partition.

---

# 3. Offset Assignment

Kafka automatically assigns Offsets in increasing order.

Example:

```text
Offset 0

Offset 1

Offset 2

Offset 3

Offset 4
```

Producer does **not** assign Offsets.

---

# 4. Offset Belongs to a Partition

Offsets are unique **only within a Partition**.

Example:

```text
Partition 0

Offset 0
Offset 1
Offset 2
```

```text
Partition 1

Offset 0
Offset 1
Offset 2
```

Both partitions can have **Offset 0**.

This is completely valid.

---

# 5. Offsets Never Change

Suppose:

```text
Offset 0

Offset 1

Offset 2
```

A new event arrives.

Kafka assigns:

```text
Offset 3
```

Existing Offsets never change or get renumbered.

---

# 6. Consumer and Offsets

Consumer reads events sequentially.

Example:

```text
Partition 0

Offset 0 → ✓ Processed

Offset 1 → ✓ Processed

Offset 2 → ✓ Processed

Offset 3 → Next Event
```

Consumer continues from the next Offset.

---

# 7. Why are Offsets Important?

Suppose the application crashes after processing:

```text
Offset 0

Offset 1

Offset 2
```

After restarting,

Consumer continues from:

```text
Offset 3
```

instead of reading everything again.

Offsets act like a **bookmark**.

---

# Doubts Solved

### Q1. Who assigns Offsets?

✅ Kafka.

Producer never assigns Offsets.

---

### Q2. Does every new event get a new Offset?

✅ Yes.

Each new event gets the next sequential Offset.

Example:

```text
Offset 5

↓

New Event

↓

Offset 6
```

---

### Q3. Can two Partitions have the same Offset?

✅ Yes.

Example:

```text
Partition 0 → Offset 0

Partition 1 → Offset 0
```

Offsets are unique only within their own Partition.

---

### Q4. Do Offsets ever change?

❌ No.

Once assigned, an Offset is permanent.

---

### Q5. Does Consumer use Offsets?

✅ Yes.

Consumer uses Offsets to remember its reading position.

After a restart or crash, it continues from the next Offset instead of starting from the beginning.

---

### Q6. Is the Offset itself changing while Consumer reads?

❌ No.

The event's Offset is fixed forever.

Only the **Consumer's reading position (bookmark)** changes as it processes more events.

---

# Flow

```text
Producer
    │
Publishes Event
    │
    ▼
Kafka
    │
Assigns Offset
    │
    ▼
Partition

Offset 0 → Event

Offset 1 → Event

Offset 2 → Event
    │
    ▼
Consumer
Reads Events Sequentially
```

---

# Remember

* **Offset** = Unique sequential number of an event **within a Partition**.
* Kafka automatically assigns Offsets.
* Offsets start from **0** in every Partition.
* Offsets never change once assigned.
* Different Partitions can have the same Offset values.
* Consumers process events sequentially and use their **saved reading position** to continue after a restart.
* **Offset** belongs to the **event**, while the **consumer's bookmark (reading position)** belongs to the **consumer**.
