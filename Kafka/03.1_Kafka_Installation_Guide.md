# 6. Copy Kafka to Ubuntu

Ubuntu can access Windows files through

```

```

Copy Kafka

# 8. One-Time Kafka Setup

These commands are executed **only once** after installing Kafka.

---

## Step 1 Generate Cluster ID

```bash
bin/kafka-storage.sh random-uuid
```

Example

```
FGPPjsgNSoCeRwPPGnknag
```

Save this ID.

---

## Step 2 Format Storage

Kafka 4.x uses **KRaft Mode**.

Format storage

```bash
bin/kafka-storage.sh format \
--standalone \
-t <ClusterID> \
-c config/server.properties
```

Example

```bash
bin/kafka-storage.sh format \
--standalone \
-t FGPPjsgNSoCeRwPPGnknag \
-c config/server.properties
```

Expected

```
Formatting dynamic metadata voter directory...
```

> **Important**
>
> Formatting is required only once.
>
> Do **NOT** run this command every time you start Kafka.

---

# 9. Start Kafka Broker

Every day whenever you want to use Kafka

```bash
bin/kafka-server-start.sh config/server.properties
```

Expected

```
Kafka Server started
```

Keep this terminal running.

# 10. Create Topic

Open another Ubuntu terminal.

Go to Kafka directory

```bash
cd ~/kafka_2.13-4.3.1/kafka_2.13-4.3.1
```

Create topic

```bash
bin/kafka-topics.sh \
--create \
--topic first-topic \
--bootstrap-server localhost:9092
```

Output

```
Created topic first-topic.
```

---

# 11. List Topics

```bash
bin/kafka-topics.sh \
--list \
--bootstrap-server localhost:9092
```

Output

```

```

Open another terminal.

```bash
bin/kafka-console-consumer.sh \
--topic first-topic \
--from-beginning \
--bootstrap-server localhost:9092

Consumer waits for messages.

-t <ClusterID> \
-c config/server.properties
```

Run these **only once** after installing Kafka.

---

## Daily Commands

```bash
cd ~/kafka_2.13-4.3.1/kafka_2.13-4.3.1

bin/kafka-server-start.sh config/server.properties
```

---

```bash
kafka-topics.sh
kafka-console-producer.sh
kafka-console-consumer.sh
```

These are used when:

* Creating new topics
* Testing Kafka
* Debugging

# 21. Key Takeaways

* Kafka 4.3.1 uses **KRaft mode** by default (no ZooKeeper).
* Storage formatting is a **one-time initialization** step.
* After the initial setup, you only need to **start the broker** for daily work.
* The console producer and consumer are primarily **learning and testing tools**. In Spring Boot applications, your Java code (`KafkaTemplate` and `@KafkaListener`) will produce and consume messages instead.
* The installation and startup flow above aligns with the official Kafka 4.3.1 quickstart, with the addition of the `--standalone` formatting option that was required for your environment.
